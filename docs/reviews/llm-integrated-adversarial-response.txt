*   **Symbol:** `scripts/cleanup_tickers.py` (Lines 144–147)
*   **Failure Scenario:** While the patch removes `_CONFIRMED_GARBAGE` to protect symbols like `UNIT`, it retains a hardcoded loop that nulls `US`, `NEW`, and `SP`. `US` (United States Steel Corp) and `SP` (SP Plus Corp) are valid, high-volume tickers. This directly contradicts the updated module-level comment (Lines 13–15) stating that spelling alone is insufficient evidence to null symbols.
*   **Minimal Fix:** Delete lines 144–147; rely on the existing `is_cash_or_fund` logic or a confirmed whitelist.

### **Severity 2: Incomplete Atomicity (Audit-Data Drift)**
*   **Symbol:** `HouseTransactionSource._save_parse_results` (Lines 256–261)
*   **Failure Scenario:** The patch moves `upsert_parse_run` after transaction replacement but fails to wrap them in a single transaction. If the process crashes or the database locks after `replace_transactions_for_docs` succeeds but before the `parse_runs` loop finishes, the database will contain new transaction data with an missing or stale `pdf_parse_runs` audit trail. This violates the "MUST" requirement specified in the prior artifact (Fix 3).
*   **Minimal Fix:** Update `Database.replace_transactions_for_docs` to accept `parse_runs` metadata and perform the `DELETE`, `INSERT` (transactions), and `UPSERT` (parse_run) within its existing `BEGIN TRANSACTION` block.
